# 🧥 KHRUSTIKS — премиум-магазин пуховиков

Одностраничный интернет-магазин пуховиков в тёмном премиум-стиле. Собрал
как учебный портфолио-кейс: сквозной сценарий покупки от первого экрана
до реальной заявки в базе данных, без CMS и фреймворков.

> Запуск локально: `python -m http.server 5178` → [http://localhost:5178](http://localhost:5178)

---

## 🎯 Что умеет

**Витрина:**
- Full-bleed hero-секция: фигура модели по центру, размытая граффити-подпись
  бренда позади, «свет от лампы» сверху
- Три товара (OBSIDIAN / ASHFALL / GLACIER — чёрный / серый / белый);
  клик по миниатюре справа переключает фото и цену в реальном времени
- Быстрый выбор размера (XS–XXL) прямо на первом экране —
  подхватывается модалкой товара, повторно выбирать не нужно
- Секция-манифест «СОЗДАН ДЛЯ ХОЛОДА / ВЫКОВАН ЧТОБЫ ВЫДЕРЖАТЬ» на
  чёрно-белом горном баннере
- Каталог трёх карточек с водяным знаком KHRUSTIKS за фигурой,
  кружком-цветом и артикулом
- Модалка товара со сменой размера и цвета, кнопка «Оформить» пробрасывает
  выбор в форму заказа
- Бегущая строка бренд-фраз под hero (бесшовный цикл через `translateX(-50%)`)

**Функционал:**
- 🔐 **Auth Gate** — Sign In / Sign Up первым экраном, glassmorphism-плашка
  поверх текстурной подложки
- 👤 **Профиль** — форма с именем, телефоном, email, адресом и способом
  оплаты. Сохраняю в `localStorage`, при следующем оформлении заказа
  подставляю в форму только пустые поля, ничего не затирая
- 🔍 **Поиск по каталогу** — модалка с живым фильтром по названию, цвету,
  артикулу
- 🛒 **Форма заказа** с валидацией и записью в реальную БД (Supabase)
- 📱 Полный адаптив, вручную прогонял на 390 / 768 / 1440 / 1980 px

**Дизайн-язык:**
- Строгая монохромная палитра (`#050505` / `#f4f2ee` / `#6d6a63`)
- Три шрифта: `Archivo Black` (дисплей), `Space Grotesk` (condensed),
  `Inter` (body)
- Тонкая SVG-плёнка шума поверх всего сайта
- Глубина через границы и `drop-shadow`, без flat-теней
- Скруглённая «плашка» сайта на фоне горы (фон вешаю на `<html>`, `<body>`
  с `margin` — сквозь margin видна гора)

## 🛠 Стек

| Слой | Что использовал |
|---|---|
| Разметка | HTML5 (семантические теги) |
| Стили | CSS3: Grid, Flexbox, **Container Queries** (`cqw`), **backdrop-filter**, CSS-переменные, SVG-фильтры |
| Скрипты | Vanilla JavaScript, без фреймворков — модалки, состояние, живой поиск, работа с REST API |
| БД | **Supabase** (PostgreSQL 17), Row Level Security |
| Шрифты | Google Fonts (Archivo Black, Space Grotesk, Inter, Rubik Mono One) |
| Локальный сервер | `python -m http.server` — сайт статический, подойдёт любой |

**Почему выбрал такой стек:**
- Vanilla JS вместо React/Vue взял осознанно: три товара, шесть модалок и
  форма — фреймворк тут только тормозит и раздувает бандл. Хотел показать,
  что понимаю платформу, а не только `create-react-app`.
- CSS Container Queries вместо media queries — потому что нужны были локальные
  реакции на ширину контейнера, а не всего окна (текст hero должен ужиматься
  синхронно с фигурой в центре, а не с viewport).
- Supabase выбрал вместо своего Node/Express-бэкенда — потому что мне нужны
  были: постгрес + REST-API + RLS «из коробки», без деплоя. Полтора часа —
  и приём заявок работает в проде.

## 🔐 Безопасность и ключи

В `script.js` захардкожен URL проекта Supabase и `publishable`-ключ. Это
сделано **сознательно**, не по ошибке — раскладываю почему.

**Что это за ключ:**

Supabase выдаёт для проекта два типа ключей:
- `publishable` (в новом формате `sb_publishable_...`) — **предназначен
  для встраивания в клиентский JS**. Аналог публикуемого key в Firebase.
- `service_role` (JWT) — **секретный**, полный доступ в обход RLS,
  только на backend.

В коде — `publishable`. Прятать его от репозитория нет смысла: сайт
статический, JS в любом случае уходит в браузер, и любой пользователь
видит ключ в DevTools → Network. Единственная реальная защита данных —
Row Level Security на уровне БД.

**Мои RLS-политики на таблице `public.khrustiks_orders`:**

```sql
alter table public.khrustiks_orders enable row level security;

create policy "Anyone can submit an order"
  on public.khrustiks_orders
  for insert
  to anon
  with check (true);
```

| Операция через `publishable`-ключ | Результат |
|---|---|
| `INSERT` (создать заявку) | ✅ разрешено |
| `SELECT` (читать чужие заявки) | ❌ политики нет → RLS блокирует |
| `UPDATE` (менять статус, цену) | ❌ политики нет → RLS блокирует |
| `DELETE` (удалить заявку) | ❌ политики нет → RLS блокирует |

Смотреть заявки могу только я через Supabase Dashboard, залогинившись
под своим аккаунтом. С `publishable`-ключа список заявок не поднять.

Подробнее — [`crm/supabase.md`](./crm/supabase.md).

## 🚀 Как запустить локально

```bash
git clone https://github.com/snajdenov707-lang/WebTest1.git
cd WebTest1

# Проект статический, сборка не нужна
python -m http.server 5178
```

Открыть: **[http://localhost:5178](http://localhost:5178)**

**Требования:** Python 3.6+ (для локального сервера) или любой другой
статический сервер — `npx serve`, VSCode Live Server, XAMPP и т.п.

**Backend Supabase уже подключён** — свой инстанс поднимать не нужно, форма
заказа сразу пишет в мою БД. Если хочешь свою:

1. Создай проект на [supabase.com](https://supabase.com)
2. Выполни в SQL Editor миграцию:
   ```sql
   create table public.khrustiks_orders (
     id uuid primary key default gen_random_uuid(),
     order_no text, product text, color text, size text, price numeric,
     name text, phone text, email text,
     city text, zip text, address text, delivery text, comment text,
     status text default 'новая', source text,
     created_at timestamptz default now()
   );
   alter table public.khrustiks_orders enable row level security;
   create policy "Anyone can submit an order"
     on public.khrustiks_orders for insert to anon with check (true);
   ```
3. В `script.js` замени `SUPABASE_URL` и `SUPABASE_KEY` (Publishable-ключ
   бери в Settings → API → Project API keys → `publishable`, не `service_role`)

## 📸 Скриншоты

### Поиск по каталогу
Модалка с живым фильтром — поиск по названию, цвету, артикулу. Открывается
из иконки лупы в шапке, оформлена в одном стиле с модалкой профиля.

![Поиск](docs/screen-search.png)

### Auth Gate — Sign In / Sign Up
Первый экран сайта: стеклянная плашка (`backdrop-filter: blur(28px)`)
поверх тёмной текстурной подложки. Переключатель вкладок, после сабмита
форма закрывается и открывается сам магазин.

![Auth Gate](docs/screen-auth.png)

### Каталог — «Новая коллекция»
Три карточки в ряд (OBSIDIAN / ASHFALL / GLACIER) с водяным знаком бренда
за фигурой, кружком цвета и артикулом.

![Каталог](docs/screen-collection.png)

### Модалка товара
Смена размера (XS–XXL) и цвета прямо в модалке; кнопка «Оформить»
пробрасывает выбор в форму заказа и скроллит к ней.

![Модалка товара](docs/screen-product-modal.png)

### Форма заказа
Валидация полей, выбор способа доставки (СДЭК / Почта / Курьер), чекбокс
согласия на обработку ПДн. Отправка — прямой POST в Supabase REST API.

![Форма заказа](docs/screen-order-form.png)

### Профиль
Модалка личного кабинета с формой контактов и способом оплаты. Данные
храню в `localStorage` и автоподставляю при следующем оформлении заказа.
Точка-индикатор на иконке в шапке подсвечивается, когда профиль заполнен.

![Профиль](docs/screen-profile.png)

## 🎨 Пайплайн работы с фото

Модели и фоны генерировал через Gemini, дальше дорабатывал руками:

1. Прикладываю референс как якорь позы, света, композиции ([`gemini-prompts.md`](./gemini-prompts.md) — все промпты и правила)
2. Gemini делает базовое фото (студийный фон `#808080` — для чистого cutout)
3. Прогоняю через remove-bg → PNG с прозрачностью (проверял: color-type 6 = RGBA)
4. Обрезаю прозрачные поля Pillow-скриптом — до плотной рамки вокруг фигуры
5. При интеграции добавляю тень через `filter: drop-shadow`

Такой пайплайн даёт три модели в разных цветах с одинаковой позой и светом —
без этого каталог из карточек смотрелся бы разнородно.

## 🔜 Что можно доработать

Честный список того, чего сейчас нет — плюс для портфолио, показывает,
что понимаю жизненный цикл продукта:

- 💳 **Реальная онлайн-оплата** — сейчас в форме только выбор способа
  (карта/наличные/перевод при получении), нет интеграции с ЮKassa/Тинькофф/Stripe
- 📦 **Расчёт доставки** — интеграция с СДЭК/Почтой России API для
  точной стоимости и сроков
- 🔔 **Уведомление менеджеру** в Telegram и на почту при новой заявке —
  через Supabase Database Webhook или Edge Function
- 🔐 **Настоящая авторизация** — Sign In / Sign Up сейчас UX-плейсхолдер
  без валидации. Полноценно — через Supabase Auth (email+пароль, OAuth)
  с личным кабинетом «мои заказы»
- 📝 **Юридические документы** — оферта, политика ПДн, реквизиты ИП/ООО,
  страница возвратов — обязательно для реальной продажи в РФ
- ⭐ **Отзывы к товарам** — блок с оценками покупателей на карточке
- 📊 **Остатки по размерам** — сейчас все размеры всегда доступны, надо
  связывать с таблицей inventory
- 🌍 **Хостинг и домен** — пока только локально и GitHub. В продакшене —
  Vercel/Netlify + свой домен, Cloudflare для картинок
- 📈 **Аналитика** — Яндекс.Метрика / GA4, событийная модель воронки
- 🖼 **Реальные фото товара** — сейчас AI-модели, для продакшена нужна
  фотосессия с профессионалом
